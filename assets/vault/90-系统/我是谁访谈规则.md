# “我是谁”访谈与个人说明

本文件是通用协作规则，内容和示例不是使用者事实。安装主流程验收通过后读取本文件；日常入口发现待开始或未完成的访谈时也读取。访谈中的逐步记录属于本流程，普通讨论仍不自动入库。

## 先查已有说明和真实位置

1. 先读本库的 `AGENTS.md`、维护规则以及已有个人说明/用户背景入口。若有 `90-系统/个人说明入口.md`，读取其中链接指向的实际文件；入口失效时先查找原文件，不另造空档案。
2. 未找到入口时，先按文件名局部查找“我是谁”“个人说明”“个人档案”“个人介绍”“自我介绍”“关于我”“用户背景”等候选，排除模板、访谈规则、示例、备份和第三方人物资料。读取候选内容与相关索引，确认是当前使用者本人，沿用已有存放位置、模板、命名和元数据；有多个档案先按明确入口和用途选择，确实无法确定才问一个定位问题，不盲目合并。
3. 已有档案无未完成标记且足够支持当前任务时，视为可用初版，不要求补做整套访谈。已知内容直接复用；旧目标或有冲突的信息标“待确认”，只在当前任务确实需要时核实。
4. 没有档案时，沿用本库长期领域的实际目录（有迁移映射则按映射），默认新建 `02-Areas-长期领域/我是谁.md`。优先用已有个人说明模板；本包没有专用模板时，按下方最小结构创建一份，沿用 `type`、`status`、`created_at`、`updated_at`、`privacy` 规则，不新增分类或虚构人物资料。个人说明是用户笔记，不能作为安装器每次覆盖的包内资产。

## 按进度决定本轮动作

以下状态是无既有规范时的约定；已有档案用其等价状态，不批量重写属性。

| 实际状态 | 本轮动作 |
| --- | --- |
| 安装验收未通过，或目录/入口/档案无法访问 | 先解决或报告具体问题；不说安装成功，不伪称已读/已保存，不开始访谈 |
| 成功、没有档案，当前可交互 | 保存最小档案、入口和待答第一题并回读，简短报成功，直接问下方第一题，然后等待 |
| 成功，但当前没有交互对话 | 保存 `待开始访谈`、入口和待答问题并回读；下次可交互使用入口接续，不承诺后台发消息 |
| `待开始访谈` | 可交互时读取已知信息，问尚未问出的第一题，记为 `访谈中`，然后等待 |
| `访谈中` / 旧档案明确未完成 | 先处理当前回答并保存；恢复会话时接续待答问题，只问一个未解决细节，不从头盘问 |
| `已暂停` / `已跳过` | 读取已有成果供相关任务参考，不自动重问或催促；用户主动说继续时从保留进度接续 |
| `初版可用` / 已完成 | 复用档案；按用户的新信息和更正更新，不因重装或更新 Skill 重开访谈 |

首次成功且没有档案时，简短报安装结果后直接说：

> 接下来我会一次问你一个问题，帮你整理一份“我是谁”的说明，以后 AI 帮你做事时可以先参考它。你可以随时说暂停或跳过。先问一个：你手头有没有一段愿意拿来参考的现成记录？比如最近的一篇笔记、一段聊天，或者一段自我介绍。

问完结束本轮，等待使用者回答；不要展示整份清单或同时问下一题。

如果使用者在当前对话中已经提供记录或明确说过没有记录，视为已经回答首题，直接按对应分支继续，不重复询问。

- 使用者提供了记录：先实际阅读；只提取与后续协作有关的内容，保留来源，并区分本人陈述、对话中他人意见和 AI 建议。记录里已经回答的内容不再问；围绕尚不明确、影响当前协作的一处提一个问题。链接或附件当前读不到时如实说明，只请求可读取的相关内容，不假装读过。
- 使用者没有记录：下一轮只问“你最近主要在做什么事情？”然后等待；已有回答涵盖此项时直接利用。
- 使用者答“不知道”：将当前问题换成最近一次具体经历，例如“最近一次你想让 AI 帮忙时，你当时在做什么？”，一次只问一件事，不代编答案。

## 访谈如何收敛

内部参考方向：当前身份与角色、最近主要事务；希望 AI 和知识库帮助解决的具体问题；试过的办法、可用经验与资料；可投入时间与常用工具等实际条件；希望 AI 如何协助（给方案或引导、原话保留、回答长度等）。

不将这些方向一次展示成问卷，不要求每项填满。每轮只问一个具体、容易回答的问题；需要追问也只追一个细节。信息足够支持当前任务时即整理可用初版，未涉及的栏目留“待补充”，以后按需补。不给固定问数，也不为填表无限追问；不默认询问与当前协作无关的私人信息。

用户说“暂停”：保存已明确内容、已回答范围、待答问题，状态改为 `已暂停`，回读后简短告知保留情况，停止提问。用户说“跳过”：不替他填答案，记录跳过项；只跳过当前题时保留后续方向并暂停本轮，跳过整个访谈时记为 `已跳过`。两者都不在同一轮连续追问，等用户继续再接续。

只写实际使用者明确提供的信息，保留有辨识度的关键原话及来源。没有答案的写“待补充”，有歧义的写“待确认”；不由语气、目录名、职业刻板印象或维护者资料推断事实。不要把示例、模板文字、AI 建议或计划记成用户经历/已实现目标。

## 逐步保存、展示和接入

每轮在继续提问前，把本轮已明确内容与最小访谈进度写入同一份个人说明，避免建立重复问答台账。保留旧原话与日期，不覆盖无关材料；写入后实际读回核对。读写失败时先如实报告并处理，不说“已保存”，也不假装下一次一定能恢复。

没有既有模板时使用以下最小结构。这里是空模板；日期替换为真实本地日期，内容以实际回答为准，不能原样存入示例信息：

```markdown
---
type: 个人说明
status: 待开始访谈
created_at: "{{date:YYYY-MM-DD}}"
updated_at: "{{date:YYYY-MM-DD}}"
privacy: 私密
---
# 我是谁

## 已明确的信息
待补充。

## 关键原话与来源
待补充。

## 访谈进度
- 最近已处理：尚未开始。
- 待答问题：你手头有没有一段愿意拿来参考的现成记录？
- 跳过项与待确认：无已记录项。
```

已有档案保留原模板与元数据，只补必要的内容和进度。提问后等待回答，不能把尚未回答的问题写成结论；正在等待第一题回答时用 `访谈中`。形成初版时记为 `初版可用`，清除已解决的待答问题，将少量未知留为待补充。简短展示已整理的几项，方便使用者纠正，不强制再答一道确认题；收到更正后实际更新并回读。

将个人说明的实际库内链接记入已有个人背景入口；没有既有约定时建立 `90-系统/个人说明入口.md`，只写标题和指向真实档案的链接即可，不复制一份内容或进度。档案、入口都要实际写入并读回，才能报告保存成功。该入口是按使用者资料生成的笔记，不放入安装覆盖清单。

后续入口（`personal-kb` 或当前宿主的持久指令）先读本库规则和上述个人说明入口，再读取当前任务必要的个人背景与相关材料。入口尚不存在时先按本文件查找已有档案；必要时补建真实链接。读到 `待开始访谈` 或 `访谈中` 且可交互时，在处理本次必要操作后接续一个问题；暂停/跳过的保持暂停，完成的直接复用。只问“知识库在哪”时仍直接给出实际位置，不为此重装或扫描全库。

读取约定只对实际发现并加载该入口、且具有文件访问权限的工具生效。文件保存、当前会话读取、宿主发现入口及跨会话加载分别核实，不把保存说成所有 AI 已经自动获得长期记忆。
